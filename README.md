# Arah (working name)

A privacy-first, open-source navigation app for Malaysia that runs in the phone's browser (PWA) on both iPhone and Android. No accounts, no login, no saved trips.

**Try it on your phone: https://yutfi.github.io/arah/**
(iPhone: open in Safari, then Share → Add to Home Screen. Android: open in Chrome, then menu → Install app. Allow location when asked.)

> **Status: early preview.** Navigation basics work. Live traffic, complete toll prices, official speed-camera data and speed limits do **not** exist yet, and the app says so on screen instead of guessing.

## What works now

- Map, current location, and search by place name, street address (falls back to the nearest area and says so) or coordinates; the result is pinned on the map first, with a Directions button. Long-press the map to drop your own pin
- **Bahasa Melayu and English**: every screen, the written turn instructions and the spoken voice. It follows the phone's language on first use and can be switched with the BM/EN button. Malay turn text is generated by `packages/core/src/malay.ts` from the route's manoeuvre types and street names (the routing server only speaks English)
- Nearby petrol, places of worship (mosque/surau, church, Chinese, Buddhist and Hindu temples, gurdwara), restaurants, entertainment, hotspots, attractions, EV charging, hospitals/clinics/pharmacies, ATMs and banks, convenience stores and supermarkets, and parking within 5 km as icons on the map, from a pre-built OpenStreetMap snapshot that loads instantly (refreshed weekly; no ratings or busy times)
- **Prayer times and Qibla**: worked out on the phone with the MIT-licensed `adhan` library (Singapore method, closest built-in match for Malaysia), no internet needed. Shown as a "next prayer" chip and a sheet. They can differ from the official JAKIM e-Solat times by a few minutes
- **Saved places** (Home, Work, where you parked, favourites) kept only on the phone in local storage; **share links** (`?to=lat,lng&n=Name`) and **Open in Waze / Google Maps / Apple Maps**
- Routes with alternatives, arrival time, "avoid tolls", and per route: traffic lights, mapped speed cameras and toll plazas counted from OpenStreetMap (volunteer data, can be incomplete). The chosen route shows them as markers on the map, and flat-rate toll plazas get a price estimate when they are on a small sourced list (`packages/core/src/tolls.ts`)
- Turn-by-turn directions with voice, current speed, rerouting when you leave the route, screen kept awake
- **Simulate drive** mode, so you can test navigation without driving
- AWAS speed-camera alert engine, built and tested, but fed by an **empty** dataset because no verified records exist yet (see `data/README.md`)

## What does not work yet

| Feature | State |
| --- | --- |
| Live traffic | Not available. See `docs/LIVE-TRAFFIC.md` for what exists and what to do next |
| Toll prices | Partial. About a dozen flat-rate plazas (Class 1 car) are priced, each from two public rate lists that agree, with source links and a check date in the code. No official machine-readable rates dataset exists. Closed systems (PLUS, ECE...) charge per entry and exit and are not priced. More plazas can be added only with two sources each |
| AWAS camera locations | Engine done, data empty. Route cards show cameras mapped on OpenStreetMap instead (not the official list, no spoken alerts from it) |
| Speed limits | Not started |
| Background navigation | Not possible in a web app (phones stop it). Needs the native apps later |
| CarPlay / Android Auto | Not started. Not claimed |

## Try it

```bash
npm install
npm run dev          # local server
npm run check        # typecheck + tests + data check + production build
```

To try it on a real phone you need an HTTPS address: see `docs/DEPLOYMENT.md` (GitHub Pages workflow included).

## How it is organised

```
apps/web         the phone app (React, TypeScript, MapLibre)
packages/core    navigation logic with no UI: distance maths, route parsing, turn tracking,
                 AWAS matching, data checks (tested; reusable by future native apps)
data/            reference datasets (AWAS cameras) with a source-and-date rule
scripts/         data validation
docs/            live traffic research, deployment
```

## Privacy: what leaves your phone

- Your position is held in memory only and discarded when the app closes. Saved places and your language choice are stored on the phone only and never uploaded. Prayer times are calculated on the phone and send nothing.
- Starting a route sends the start and end points to the routing server. Search sends what you type, plus a nearby point, to the search server. Tiles are fetched from the map server.
- By default those are public demo servers run by others (see `docs/DEPLOYMENT.md`). They see your network address like any website does.

## Data rules

Nothing is invented. A speed-camera record is used only if it has a source URL and a verification date. Run `npm run validate-data` to check, and CI does the same on every change.

## Testing notes

- `packages/core` has 56 automated tests (geometry, route parsing, progress tracking, off-route detection, AWAS matching and data gate, toll estimate rules, nearby categories, Malay turn text).
- The app was also exercised in a headless browser with the network calls faked: search, route options, simulated drive to arrival, camera alert, about screen. That test used made-up roads and a made-up camera, only inside the test.
- The Malay screens, Malay turn text and voice language (`ms-MY`), prayer sheet, saved places, share link and open-in links were exercised the same way (made-up place and route, network faked).
- **Not yet tested:** real GPS on a real phone, the real public servers, iOS Safari voice and wake-lock behaviour, whether a phone has a Malay voice installed (without one the phone may read Malay text with an English voice or stay silent), prayer times against the official JAKIM e-Solat table, and the Malay wording by a native speaker (please report anything that sounds wrong).
